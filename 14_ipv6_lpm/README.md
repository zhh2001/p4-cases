# Case 14：IPv6 最长前缀路由

本案例使用 128 位目的地址查询 LPM 表，选择下一跳后改写以太网 MAC，并将 `hopLimit` 减一。`/128` 路由与父级 `/64` 使用不同下一跳，可以从接收主机和目的 MAC 验证最长前缀匹配。

## 拓扑与路由

三个主机分别连接交换机的端口 1、2、3：

```text
h1 (port 1) -- s1 -- (port 2) h2
               |
            (port 3)
               h3
```

| 主机 | MAC                 | CLI 中配置的 IPv6 地址 |
| ---- | ------------------- | ---------------------- |
| h1   | `00:00:00:00:00:01` | `2001:db8:1::1/64`     |
| h2   | `00:00:00:00:00:02` | `2001:db8:2::1/64`     |
| h3   | `00:00:00:00:00:03` | `2001:db8:3::1/64`     |

控制器安装四条路由：

| 前缀                 | 出口   | 下一跳 MAC |
| -------------------- | ------ | ---------- |
| `2001:db8:1::/64`    | port 1 | h1 MAC     |
| `2001:db8:2::/64`    | port 2 | h2 MAC     |
| `2001:db8:3::/64`    | port 3 | h3 MAC     |
| `2001:db8:3::42/128` | port 2 | h2 MAC     |

发往 `2001:db8:3::42` 的包从端口 2 转发，邻近地址 `::41`、`::43` 及 h3 自身地址 `::1` 从端口 3 转发。h2 是该主机路由指定的下一跳，测试检查报文到达下一跳的完整帧。

## 数据面处理

解析器读取 40 字节 IPv6 基本头，检查版本为 6，并确认声明的负载长度不超过帧中可用的字节数。负载长度包含扩展头，检查使用 32 位算术。

解析错误、非 IPv6 帧、`hopLimit` 为 0 或 1，以及目的地址没有匹配路由时丢弃。其他报文按最长前缀查询结果转发：

- 目的 MAC 改为路由中的下一跳 MAC。
- 源 MAC 改为入包的目的 MAC，即本示例使用的网关 MAC。
- `hopLimit` 减一。
- 保留其余基本头字段、扩展头、传输层负载和以太网填充。

IPv6 基本头没有校验和。源、目的 IPv6 地址和传输层内容保持不变，UDP、TCP 和 ICMPv6 校验和也保持不变。基本头之后的数据按原始字节转发，扩展头和传输层内部格式不在本案例的解析范围内。字段定义及转发规则见 [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html#section-3)。

## 自动验证

默认发送 228 个报文，其中 159 个应转发，69 个应丢弃。h1、h2、h3 应分别收到 18、78、63 个完整帧。

测试覆盖：

- 三台主机之间的双向 UDP、TCP 和 ICMPv6 流量。
- `/128` 覆盖父级路由、相邻地址回退到 `/64`、子网起止地址及无路由地址。
- `hopLimit` 为 0、1、2、255，最小 UDP、奇数负载、1500 字节 IP 报文、零负载和非零填充。
- Hop-by-Hop 与 Destination Options 链，以及可完整重组的 UDP 和 TCP 分片组。
- 异常版本、负载长度超出实际报文、截断头部与负载、非 IPv6 帧及 ARP 的丢弃。

三个主机同时抓取入向报文，测试逐字节核对每个出口的全部预期帧。少包、重复、错出口、丢弃报文泄漏，或 MAC、跳数、负载被意外改动都会失败。

自动测试使用带随机标记的网关 MAC，并关闭本次拓扑接口的内核 IPv6，避免邻居发现和内核响应干扰。原始以太帧仍由 P4 完整处理。发送和抓包进程必须成功退出并返回有效结果，超时或控制器提前退出会使测试失败。结束时清理本次进程和网络。

## 运行

```bash
sudo ./run.sh
sudo ./run.sh cli
```

CLI 中配置上述 IPv6 地址。跨网段探测使用原始以太帧，并指定网关 MAC `00:00:00:00:0a:01`。本案例演示静态路由，邻居发现与 ICMP 错误生成需要另行实现。

默认测试输出：

```text
ipv6 router ready: 4 LPM routes installed
IPv6 probes: sent=228 forwarded=159 dropped=69
SUCCESS: IPv6 longest-prefix routing and complete frames validated
```

在仓库根目录运行回归测试：

```bash
/usr/bin/python3 -m unittest discover -s tests -p test_ipv6_lpm.py -v
go test ./14_ipv6_lpm/controller
```

## 文件说明

| 文件                 | 用途                                     |
| -------------------- | ---------------------------------------- |
| `main.p4`            | IPv6 解析校验、LPM 查询及 MAC 和跳数更新 |
| `controller/main.go` | 安装 pipeline 和四条 IPv6 路由           |
| `topology.py`        | 管理拓扑、核对三端完整报文及清理进程     |
| `packets.py`         | 生成流量并独立计算下一跳与预期帧         |
| `probe.py`           | 发送报文清单并抓取带标记的入向报文       |
| `run.sh`             | 编译、启动、自动验证和资源清理           |
